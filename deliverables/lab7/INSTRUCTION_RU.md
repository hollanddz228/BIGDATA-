# Как выполнить и защитить лабораторную №7 на Windows

**Студент:** Табидулла Абылайхан. **Группа:** АЖ45. **Вариант:** 7 — больница, `patients`.

В этом руководстве используется архив `Lab7_AZh45_Patients_Complete.zip`, уже находящийся в этой папке. Повторно скачивать архив ради инструкции не нужно. Все упомянутые данные и сценарии уже есть в нём.

Основной путь: **Windows → Docker Desktop → PowerShell → mongosh и cqlsh**. MongoDB и Cassandra работают как настоящие серверы внутри контейнеров. Python для ручного выполнения по этому руководству не требуется.

| Требование | Демонстрация |

| Минимум 500 записей | До удаления: **768** |

Готовый Word-отчёт написан на казахском. Его результаты и скриншоты получены при выполнении в облачной среде. После собственного запуска можно заменить скриншоты на свои, сохранив структуру и проверив совпадение результатов.

## 3. Подготовить Docker Desktop

1. Скачай Docker Desktop с официального сайта: https://docs.docker.com/desktop/setup/install/windows-install/ . Проверь требования установщика к своей версии Windows.
2. При установке используй Linux-контейнеры и WSL 2 backend.
3. Если требуется WSL, открой PowerShell **от имени администратора** и выполни:

```powershell
wsl --install
```

4. Выполни предложенную Windows перезагрузку. При необходимости заверши первоначальную настройку Ubuntu.
5. Запусти Docker Desktop и дождись запуска движка. В настройках **General** должен использоваться WSL 2 based engine.
6. Открой обычный PowerShell. Администраторские права для остальных команд обычно не нужны.

Проверка в **PowerShell**:

```powershell
docker version
```

В выводе должны присутствовать **Client** и **Server**. Если есть только Client и сообщение о недоступном сервере, сначала запусти Docker Desktop.

Для комфортной работы желательно 8–16 ГБ ОЗУ и около 10 ГБ свободного места. При недостатке памяти закрой тяжёлые программы. В примере heap Cassandra ограничен 1 ГБ, но контейнеру также нужна память вне heap.

## 4. Открыть рабочую папку и запустить серверы

Все команды этого раздела вводятся в **PowerShell**, по одной строке.

```powershell
Set-Location 'C:\BigDATA\lab7'
Get-ChildItem
Test-Path .\data\patients.json
```

Последняя команда должна вывести `True`.

Скачать образы:

```powershell
docker pull mongo:7.0.16
docker pull cassandra:4.1.7
```

Первое скачивание может занять несколько минут.

Создать MongoDB:

```powershell
docker run -d --name lab7-mongo -p 127.0.0.1:27018:27017 -v lab7-mongo-data:/data/db mongo:7.0.16 --bind_ip_all
```

Создать Cassandra:

```powershell
docker run -d --name lab7-cassandra -p 127.0.0.1:9042:9042 -e CASSANDRA_CLUSTER_NAME=Lab7Hospital -e MAX_HEAP_SIZE=1G -e HEAP_NEWSIZE=256M -e CASSANDRA_CONCURRENT_READS=8 -e CASSANDRA_CONCURRENT_WRITES=8 -v lab7-cassandra-data:/var/lib/cassandra cassandra:4.1.7
```

Эти команды создают контейнеры один раз. Если контейнеры с такими именами уже существуют, вместо повторного `docker run` используй:

```powershell
docker start lab7-mongo lab7-cassandra
```

Проверить, что контейнеры запущены:

```powershell
docker ps
```

Проверить готовность MongoDB:

```powershell
docker exec lab7-mongo mongosh --quiet --eval 'db.adminCommand({ping:1})'
```

Ожидается `ok: 1`.

Проверить готовность Cassandra:

```powershell
docker exec lab7-cassandra cqlsh -e "SELECT release_version FROM system.local;"
```

Ожидается версия `4.1.7`. Первый запуск Cassandra обычно занимает дольше MongoDB. Если получено `Connection refused`, подожди 30–60 секунд и проверь снова. Если ошибка сохраняется, посмотри:

```powershell
docker logs --tail 60 lab7-cassandra
```

## 6. MongoDB: выполнить все действия вручную

В **PowerShell** открой shell MongoDB:

```powershell
docker exec -it lab7-mongo mongosh
```

Теперь команды вводятся **в mongosh**, где приглашение будет вида `test>` или `hospital_lab7>`. Не вводи эти приглашения как часть команды.

### 6.1. Выбрать базу и создать коллекцию

```javascript
use hospital_lab7
```

Создай коллекцию со схемой. Условие позволяет выполнить блок повторно, если коллекция уже существует:

```javascript
if (!db.getCollectionNames().includes("patients")) {
  db.createCollection("patients", {
    validator: {
      $jsonSchema: {
        bsonType: "object",
        required: ["id", "name", "age", "diagnosis", "room"],
        properties: {
          id: {bsonType: "int", minimum: 1},
          name: {bsonType: "string"},
          age: {bsonType: "int", minimum: 21, maximum: 120},
          diagnosis: {bsonType: "string"},
          room: {bsonType: "int", minimum: 101}
        }
      }
    }
  });
}
db.patients.createIndex({id: 1}, {unique: true})
show collections
```

`patients` должна появиться в списке. Индекс запрещает повторяющийся пользовательский `id`. Автоматическое поле `_id` MongoDB также остаётся в документах.

### 6.2. Загрузить 768 записей

Следующая очистка относится **только к учебной коллекции `hospital_lab7.patients`**. Она нужна, чтобы повторное выполнение начиналось с исходного набора. Не используй эту базу для посторонних данных.

```javascript
db.patients.deleteMany({})
var importedPatients = JSON.parse(require("fs").readFileSync("/tmp/patients.json", "utf8")).map(p => ({...p, id: NumberInt(p.id), age: NumberInt(p.age), room: NumberInt(p.room)}))
var importResult = db.patients.insertMany(importedPatients)
printjson({acknowledged: importResult.acknowledged, insertedCount: Object.keys(importResult.insertedIds).length})
db.patients.countDocuments({})
```

Ожидается `insertedCount: 768` и общий счётчик `768`. `insertedCount` здесь вычислен из числа возвращённых `insertedIds`.

### 6.3. Вывести все записи

```javascript
db.patients.find({}, {_id: 0}).sort({id: 1}).forEach(p => printjson(p))
```

Команда выводит все 768 документов. Обычный `find()` в интерактивном shell показывает результат порциями; `forEach()` выводит всё.

Для отдельного короткого скриншота:

```javascript
db.patients.find({}, {_id: 0}).sort({id: 1}).limit(10)
```

### 6.4. Найти пациента по ID

```javascript
db.patients.findOne({id: 3}, {_id: 0})
```

Ожидаемые значения: `id=3`, `name="Пациент-0003"`, `age=32`, `diagnosis="Диабет: оң нәтиже"`, `room=103`.

### 6.5. Изменить числовое поле

```javascript
db.patients.findOne({id: 2}, {_id: 0})
db.patients.updateOne({id: 2}, {$set: {room: NumberInt(215)}})
db.patients.findOne({id: 2}, {_id: 0})
```

Палата должна измениться **102 → 215**. В результате UPDATE: `matchedCount=1`, `modifiedCount=1`.

### 6.6. Удалить одну запись

```javascript
db.patients.findOne({id: 768}, {_id: 0})
db.patients.deleteOne({id: 768})
db.patients.findOne({id: 768})
```

Ожидается `deletedCount=1`, затем `null`.

### 6.7. Посчитать оставшиеся

```javascript
db.patients.countDocuments({})
```

Ожидается **767**.

### 6.8. Числовое условие

```javascript
db.patients.countDocuments({age: {$gt: 40}})
db.patients.find({age: {$gt: 40}}, {_id: 0}).sort({id: 1}).limit(5)
```

Ожидается **194** подходящих записи. `$gt` означает «строго больше», поэтому возраст 40 не включается.

### 6.9. Сортировка по возрасту

```javascript
db.patients.find({}, {_id: 0}).sort({age: -1, id: 1}).limit(5)
```

Первые возраста: **81, 72, 70, 69, 69**. `-1` — убывание; `id:1` упорядочивает записи одинакового возраста по ID.

### 6.10. Дополнительная задача: фильтр + сортировка

```javascript
db.patients.find({age: {$gt: 40}}, {_id: 0}).sort({age: -1, id: 1}).limit(5)
```

Сделай скриншот команды и результата. `limit(5)` ограничивает только показ; подходящих записей по-прежнему 194.

Завершить shell MongoDB:

```javascript
exit
```

## 7. Cassandra: выполнить все действия вручную

Вернувшись в **PowerShell**, выполни:

```powershell
docker exec -it lab7-cassandra cqlsh
```

Теперь команды вводятся **в cqlsh**. В конце CQL-команд нужна точка с запятой. Приглашение обычно имеет вид `cqlsh>` или `cqlsh:hospital_lab7>`.

### 7.1. Создать keyspace и таблицу

```sql
CREATE KEYSPACE IF NOT EXISTS hospital_lab7
WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};

USE hospital_lab7;

CREATE TABLE IF NOT EXISTS patients (
    id int PRIMARY KEY,
    name text,
    age int,
    diagnosis text,
    room int
);

DESCRIBE TABLE patients;
```

`SimpleStrategy` с RF=1 соответствует одному учебному узлу. В этой схеме `id` является partition key.

### 7.2. Ввести 768 записей

Очистка ниже относится только к учебной таблице этого варианта и позволяет воспроизвести исходный набор при повторном выполнении:

```sql
TRUNCATE patients;
SOURCE '/tmp/lab7_insert.cql';
SELECT COUNT(*) FROM patients;
```

Ожидается **768**. Успешные INSERT часто не выводят отдельного сообщения — проверяй результат через SELECT.

### 7.3. Вывести все записи

```sql
PAGING OFF;
SELECT * FROM patients;
```

Внизу должно быть **`(768 rows)`**. В отличие от MongoDB-запроса с `sort({id:1})`, этот SELECT не обещает сортировку по ID. Иной порядок строк нормален.

### 7.4. Поиск по ID

```sql
SELECT * FROM patients WHERE id = 3;
```

Одна строка: возраст 32, палата 103, положительный признак диабета.

### 7.5. Изменение палаты

```sql
SELECT id, room FROM patients WHERE id = 2;
UPDATE patients SET room = 215 WHERE id = 2;
SELECT id, room FROM patients WHERE id = 2;
```

Ожидается **102 → 215**.

### 7.6. Удаление

```sql
SELECT * FROM patients WHERE id = 768;
DELETE FROM patients WHERE id = 768;
SELECT * FROM patients WHERE id = 768;
```

Последний запрос должен вернуть **`(0 rows)`**.

### 7.7. Итоговый счётчик

```sql
SELECT COUNT(*) FROM patients;
```

Ожидается **767**. Предупреждение `Aggregation query used without partition key` сообщает о полном сканировании таблицы. Для учебных 768 строк это ожидаемо; для больших таблиц такой подход дорог.

### 7.8. Два разных запроса по ID

```sql
SELECT * FROM patients WHERE id = 1;
SELECT id, name, age, diagnosis, room FROM patients WHERE id IN (1, 2, 3);
```

Первый возвращает одну строку, второй — три строки. Первый обращается к одному ключу раздела, второй — к нескольким. Порядок строк IN-запроса не гарантируется.

Пункты 8–9 задания (свободное сравнение возраста и сортировка) выполняются в MongoDB. Для подобных запросов в Cassandra нужна другая, специально спроектированная таблица. Здесь не нужно добавлять `ALLOW FILTERING` или пытаться выполнить глобальный `ORDER BY age`.

Выйти из cqlsh:

```sql
EXIT;
```

## 8. При желании показать MongoDB в Compass

Compass необязателен: mongosh уже соответствует требованиям задания.

1. Установи MongoDB Compass: https://www.mongodb.com/try/download/compass .
2. Оставь Docker Desktop и контейнер `lab7-mongo` включёнными.
3. Подключись по строке `mongodb://127.0.0.1:27018`.
4. Открой `hospital_lab7` → `patients` → **Documents**.
5. Для поиска заполни Filter: `{"id":3}`.
6. Для дополнительной задачи Filter: `{"age":{"$gt":40}}`, Sort: `{"age":-1,"id":1}`. Поле Sort находится в параметрах запроса; расположение зависит от версии Compass.
7. Нажми **Find** и сделай скриншот, на котором видны подключение, коллекция, запрос и результат.

Не импортируй patients.json ещё раз поверх итогового состояния: это не требуется для просмотра и может вызвать ошибку уникального ID.

## 10. Как показать работу преподавателю за 5–7 минут

До занятия проверь Docker Desktop, готовность обеих баз и возможность открыть отчёт. Если ноутбук перезагружался, запусти контейнеры снова; импорт заново не требуется.

1. Покажи титульный лист: ФИО, АЖ45, вариант 7, тема «Аурухана».
2. Объясни источник данных и происхождение каждого поля.
3. В mongosh покажи итоговый `countDocuments({})` — 767, `findOne({id:3})`, `id=2` с room=215, отсутствие id=768.
4. Выполни MongoDB-запрос `age > 40`: число 194; покажи фильтр вместе с сортировкой.
5. В cqlsh покажи COUNT=767, id=3, room=215 у id=2, отсутствие id=768.
6. Выполни `WHERE id=1` и `WHERE id IN (1,2,3)`, объясни разницу.
7. Открой сравнение систем и вывод в отчёте. До/после UPDATE и DELETE покажи на собственных скриншотах.

Для живого показа самого изменения и удаления, а не только их итогов, выполни полный ручной цикл разделов 6–7 перед преподавателем либо заранее восстанови исходный учебный набор по пунктам 6.2 и 7.2. После восстановления будет 768 записей и room=102; тогда последующие UPDATE/DELETE снова покажут ровно изменения из отчёта.

В уже готовом итоговом состоянии повторный UPDATE на 215 даст modifiedCount=0 в MongoDB, а повторный DELETE id=768 — deletedCount=0. Это означает, что соответствующие действия уже выполнены. Для повторной демонстрации сначала восстанови начальное состояние.

### Короткое выступление на казахском

> Менің зертханалық жұмысымның нұсқасы — №7, тақырыбы — «Аурухана». MongoDB жүйесінде patients коллекциясын, Cassandra жүйесінде patients кестесін құрдым. Ашық Pima Indians Diabetes дереккөзінен 768 медициналық жазба алынды. Жас пен диабет белгісі бастапқы деректерден алынған, ал пациент кодтары мен палата нөмірлері оқу үшін шартты берілген. Екі жүйеде деректерді енгізу, оқу, өзгерту және жою операцияларын орындадым. Екінші пациенттің палатасын 102-ден 215-ке өзгерттім, 768-нөмірлі жазбаны жойдым. Соңында екі базада да 767 жазба қалды. MongoDB-де жасы 40-тан жоғары 194 пациент табылып, жас бойынша кему ретімен сұрыпталды. Cassandra-да ID теңдігі және ID жиыны бойынша сұраныстар орындалды.

### Вопросы, которые могут задать

- **Откуда данные?** Открытая медицинская база Pima Indians Diabetes; исходный владелец NIDDK. Исходный CSV, описание, версия GitHub-зеркала и SHA-256 есть в архиве.
- **Все поля реальные?** Нет. Возраст и бинарный признак диабета — из источника. ID — номер строки, name — условный код, room — учебное число. Это не журнал реальных госпитализаций.
- **Почему 767, если было 768?** Одну запись удалили по заданию.
- **Почему результат по возрасту 194?** Это число оставшихся записей со значением age строго больше 40.
- **Почему возраст не меняли?** Задание требует изменить числовое поле. Изменили room, сохранив исходный медицинский возраст.
- **Чем _id отличается от id?** _id — штатный ключ MongoDB; id — учебный номер из варианта, дополнительно защищённый уникальным индексом.
- **Почему Cassandra не сортирует так же?** В этой таблице id — ключ раздела, clustering key нет. Cassandra требует проектировать модель под запрос; произвольная глобальная сортировка по age не поддерживается этой схемой.
- **Что значит RF=1?** Одна копия данных для одного учебного узла; репликация между несколькими узлами здесь не демонстрируется.
- **Доказывают ли 768 строк производительность Big Data?** Нет. Они выполняют объём задания и демонстрируют CRUD. Производительность больших кластеров здесь не измерялась.

## 12. Типичные проблемы

| Сообщение / ситуация | Действие |
|---|---|
| `docker` не найден | Заверши установку Docker Desktop и открой новый PowerShell. |
| Cannot connect to Docker daemon | Запусти Docker Desktop и дождись готовности движка. |
| Контейнер с таким именем уже существует | Используй `docker start`, не создавай новый контейнер с тем же именем. |
| Connection refused в cqlsh | Дождись запуска Cassandra; проверь `docker logs --tail 60 lab7-cassandra`. |
| Cassandra завершилась, код 137 / OOM | Проверь доступную память и лимит Docker/WSL; закрой тяжёлые программы, увеличь доступную память и снова запусти контейнер. |
| Port is already allocated | Выполни `docker ps` и проверь, нет ли уже твоего контейнера на этом порту. Не останавливай неизвестные сервисы. Если порт занят другой установкой MongoDB/Cassandra, нужно согласованно сменить host-порт и подключение. |
| Файл не найден при docker cp | Проверь `Set-Location` и `Test-Path .\data\patients.json`; не работай внутри нераспакованного ZIP. |
| `/tmp/patients.json` или CQL-файл не найден | Повтори нужный `docker cp` из раздела 5. |
| `E11000 duplicate key` | Повторный импорт идёт поверх существующих ID. Для нового полного цикла используй учебную очистку из 6.2 и затем импорт. |
| Document failed validation | Проверь NumberInt в импортирующей команде: схема ожидает целые числа. |
| `modifiedCount=0` или `deletedCount=0` | Изменение/удаление уже выполнено. Для нового цикла восстанови набор по 6.2 и 7.2. |
| CQL ждёт продолжение `...` | Проверь закрывающие скобки, кавычки и точку с запятой. Ctrl+C отменяет незавершённую команду. |
| После правки Word PDF остался старым | Экспортируй PDF заново из изменённого Word. |

## 13. Необязательный автоматический прогон

Если у тебя установлен Python, вместо ручного выполнения CRUD можно запустить готовый `scripts/run_tasks.py`. Он использует Docker CLI и стандартную библиотеку Python. Сначала выполни запуск серверов и дождись их готовности, затем в PowerShell из папки `lab7`:

```powershell
py -3.12 -X utf8 scripts/prepare_data.py
py -3.12 -X utf8 scripts/run_tasks.py
```

Используй доступную установленную версию Python; вариант `-3.12` предполагает, что Python 3.12 установлен. Сценарии пересоздают учебные записи, выполняют все команды, сохраняют свежие журналы в results. Итоговое сообщение: `MONGOSH_AND_CQLSH_TASKS_COMPLETED`.

Это альтернативный способ выполнить операции, а не обязательный дополнительный шаг после ручной работы. Он снова приводит обе базы к итоговым 767 записям. Отдельная проверка `verify_results.py` требует Python-драйверов из requirements; создание новых отчётных скриншотов и Word — дополнительных инструментов. Для ручного выполнения и защиты по разделам 1–12 они не нужны.

В текущем Windows-варианте внешний порт MongoDB — **27018**, внутренний — 27017. Если используешь исходный `verify_results.py`, предварительно замени в его MongoDB URI `mongodb://127.0.0.1:27017/` на `mongodb://127.0.0.1:27018/`. Команды `docker exec ... mongosh` продолжают работать без изменения внутреннего порта.
